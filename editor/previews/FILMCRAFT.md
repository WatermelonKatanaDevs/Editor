# FilmCraft integration

FilmCraft is pinned as a Git submodule at `editor/previews/vendor/filmcraft-src` from https://github.com/storytold/filmcraft.

- License: MIT OR Apache-2.0.
- Browser target: `apps/filmcraft-web`, built with `cargo xtask web` and the matching `wasm-bindgen-cli` version.
- Standalone output: `editor/previews/vendor/filmcraft/`, generated by `scripts/build-filmcraft.mjs` and published with the other standalone apps.
- Standalone URL: `https://watermelonkatanadevs.github.io/Editor/editor/previews/vendor/filmcraft/`.

The standalone app works without the Editor and keeps its native browser file dialogs and download-based saves. When embedded, the Editor uses FilmCraft's upstream `?host=parent` contract. Its internal Open, import, and relink commands use the single Editor-owned `editor/lib/workspace-picker.js` UI. Project files are passed through the FilmCraft host protocol; media files are returned to FilmCraft as ordinary `File` objects so import and relink preserve their normal behavior. It can open workspace or device files, and project saves, Save As, and exports are written through the same shared workspace save dialog. Workspace saves mark the Editor project dirty and refresh Explorer. Save As and export destinations use the shared save dialog; the FilmCraft Exports folder is used as the suggested starting location when it exists. Project saves remain associated with the opened workspace project. A read-only workspace can open files but cannot save them.

The host bridge requires the Editor and FilmCraft iframe to share an origin. The host-mode open message has a 512 MiB per-file limit (and FilmCraft limits whole-project reads to 256 MiB). FilmCraft uses WebGPU with a WebGL2 fallback and does not require cross-origin isolation headers. Keep backup copies of important edits while evaluating the integration.
